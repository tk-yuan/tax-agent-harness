# 结论报告撰写

## 何时使用

任务收尾、需要交付一份可存档、可复核的材料时。

## 要求

报告必须让**没参与过程的人能复核每一句话**。所以：

1. **每个税额数字都要能追溯到工具输出**。写"累计应纳税额 1,234.5 万元"，
   要说明它来自哪次 `tax_calc` / `optimize_plan` 调用、算例编号是什么。

2. **每个政策依据都写文号**。不写"根据小型微利企业优惠政策"，要写
   "根据《财政部 税务总局关于……的公告》（财政部 税务总局公告 20XX 年第 X 号）"。

3. **区分事实、推断和假设**。三类内容分节写：
   - 事实：工具算出来的数字、政策原文
   - 推断：基于事实的解释（如"扣除之所以应前置，是因为……"）
   - 假设：模型输入的前提（如收入预测、资产购置年份）

4. **主动写局限**。这个方案在什么条件下会失效？哪些数据是估计的？
   没写局限的报告，专业度反而更低。

## 产出方式

用 `write_file` 落到 `workspace/reports/` 下，而不是把全文塞进对话。
写完后在对话里只给**摘要 + 文件路径**，让上下文保持轻量。

报告骨架：

```
# 筹划方案：<企业/算例>

## 一、企业画像与输入假设
## 二、适用政策及依据（逐条列文号与有效期）
## 三、方案与测算结果（附与基线的对照）
## 四、方案有效性的解释
## 五、风险与局限
## 六、附录：核算明细（可另存文件）
```
